# Wan 3.0 图生视频与提示词指南

整理日期：2026-09-30

项目接入更新：2026-10-01，支持按分镜顺序自动衔接首尾帧。

本文依据[万相 3.0 视频生成使用指南](https://help.aliyun.com/zh/model-studio/wan3-video-generation-guide)、[万相 3.0 视频生成 Prompt 指南](https://help.aliyun.com/zh/model-studio/wan3-video-generation-prompt-guide)和[视频生成 API 参考](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)，说明如何从一张或两张图生成视频，以及如何编写提示词。

## 选择图生视频模式

| 模式 | 输入画面 | 模型要生成什么 | 适用场景 |
| --- | --- | --- | --- |
| 首帧生视频 | `first_frame` | 从指定的开场画面继续运动 | 角色或场景已有选定画面，结尾可以开放 |
| 首尾帧生视频 | `first_frame` + `last_frame` | 在指定起点和终点之间补运动 | 需要固定结尾姿势、镜头构图或转场画面 |

官方素材组合未支持仅传 `last_frame`。本项目每个镜头都使用自己的首帧，尾帧可选；没有尾帧时只传 `first_frame`。

两种模式都可以在提示词中指定人物动作、运镜、对白和音效。官方建议把 `ratio` 设为 `adaptive`，让输出画幅跟随输入图。可设置 `duration` 为 2–30 秒的整数，或 `-1` 让模型估算时长；需要精确分镜时建议直接指定时长。

首尾帧模式与全能参考素材模式互斥：请求使用 `first_frame` / `last_frame` 时，不能同时传 `reference_image`、`reference_video`、`reference_audio`、`file` 或 `link`。如果重点是让模型记住额外的角色参考图或音频，应考虑参考素材模式，不能把它们附加到首尾帧请求。

首尾帧在画幅、角色、服装、场景和光线上的差异越小，提示词指定的过渡越简单，越容易得到连贯结果。这是制作建议；模型仍会自行补全两张图之间的细节，实际效果需要生成后检查。

## API 请求结构

视频任务通过异步接口提交，再用返回的 `task_id` 查询结果。下面是首尾帧模式的请求结构：

```bash
curl --location 'https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/video-generation/video-synthesis' \
  -H 'X-DashScope-Async: enable' \
  -H "Authorization: Bearer $DASHSCOPE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "wan3.0-video",
    "input": {
      "prompt": "这里填写下文的首尾帧提示词",
      "media": [
        {"type": "first_frame", "url": "https://example.com/start.png"},
        {"type": "last_frame", "url": "https://example.com/end.png"}
      ]
    },
    "parameters": {
      "resolution": "720P",
      "ratio": "adaptive",
      "duration": 8,
      "audio": true,
      "prompt_extend": false
    }
  }'
```

首帧模式只需在 `media` 中保留 `first_frame`。图片可使用服务商能访问的 HTTPS 地址或支持的图片 Data URI；本项目的图片保存在账号私有素材库，接入时由服务端读取图片内容并以内嵌 Data URI 发送，不应把登录后的 `/api/assets/...` 地址直接交给模型。

请求返回 `output.task_id` 后，可按官方接口查询：

```bash
curl 'https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/tasks/{task_id}' \
  -H "Authorization: Bearer $DASHSCOPE_API_KEY"
```

文档示例使用北京地域。调用时，模型、业务空间 Endpoint 和 API Key 必须属于同一地域；请按账号和模型实际开通地域配置，不要只根据应用服务器所在位置选择地域。

## 怎样组织提示词

官方给出的完整要素可以按需组合：

```text
提示词 = 总体描述
       + 参考素材说明（使用参考素材模式时）
       + 带时间段的动作与镜头描述
       + 台词
       + 音效 / BGM
       + 风格与情绪
       + 不希望出现的内容
```

对于首帧或首尾帧模式，起点和终点画面已经由图片约束。提示词可简化为：

1. 写清这是一段怎样的镜头：单镜头或一镜到底、镜头节奏、整体情绪。
2. 按时间顺序写动作的起始姿势、变化过程和结束姿势，使用明确的动作词和方向。
3. 写清运镜方式及速度，例如固定机位、缓慢推近或平稳环绕；复杂动作中减少频繁切换景别。
4. 首尾帧模式说明如何从起始状态过渡到尾帧，并让最后一段动作自然落在尾帧姿态和构图上。
5. 需要原生声音时写明说话人、台词、说话时间或语气，并说明环境声及 BGM；不需要某类声音时明确写“无台词”或“无背景音乐”。
6. 仅列出重要的负向要求，例如不要字幕、水印、换脸或服装改变；不要重复提示词里已经满足的正向要求。

时间戳适合表达一段视频里的节奏变化，写法可以是 `[0–2秒]` 或 `镜头1（00:00–00:02）`。同一提示词保持一种格式。时间段应覆盖目标时长，避免空档和重叠；每一段描述少量、可理解的动作，不要堆叠互相冲突的运镜指令。

在提示词里称“首帧画面”或“尾帧画面”，指清楚当前请求中是哪张图。只有真的传入参考素材时，才使用“图1”“视频1”等编号，避免提示词引用未上传的素材。

## 提示词示例

下面示例中的人物和场景描述是原创模板，可替换为自己的分镜内容。

### 首帧生视频：从已选画面继续动作

输入首帧：雨夜屋檐下，短发少女握着一把红伞，身体侧对镜头，远处有暖色街灯。

```text
生成一段 5 秒的动漫单镜头，保持首帧画风、人物发型、服装、红伞和雨夜街景一致，不切镜。
[0–2秒] 固定中景，少女保持侧身，雨水沿伞沿落下，她缓慢抬眼看向街道。
[2–5秒] 镜头平稳缓慢推近，少女轻轻转向镜头，红伞随手腕略微倾斜，发梢和衣袖被微风带动；动作在面部近景中自然收住。
保留细微雨声，无对白、无背景音乐。不要字幕、文字、水印、换脸或服装变化。
```

### 首尾帧生视频：从起始画面过渡到指定结尾

输入首帧：少女站在庭院石阶下，手里拿着未打开的信。输入尾帧：她坐在台阶上，信已展开，抬头望向晨光。

```text
生成一段 8 秒的动漫单镜头，一镜到底，不切镜。沿用首帧和尾帧中的同一位少女、发型、服装、庭院布局和柔和手绘风格。
[0–2秒] 固定中景，少女低头看着手中的信，树叶轻轻摇动，阳光穿过枝叶。
[2–6秒] 镜头缓慢向右侧平移并略微推近；少女沿石阶坐下，平稳展开信纸，视线从信纸移向前方。动作连续，人物不瞬移，服装和发型保持不变。
[6–8秒] 镜头停止移动，少女抬头望向晨光，嘴角露出释然的笑容；姿态、视线和构图自然过渡到尾帧画面，并在最后定格。
只有庭院鸟鸣与轻风声，无对白、无背景音乐。不要字幕、文字、水印或额外人物。
```

首尾帧提示词的重点是“怎样到达尾帧”，而不是再次详细复述尾帧里已经能看见的静态内容。如果两张图在人物姿势或景别上变化很大，就在提示词中为中间的姿势变化留出时间，不要要求模型瞬间完成多个转换。

## 本项目的独立首帧、可选尾帧与提示词

每个镜头使用自己的选定图片作为 `first_frame`，包括第一个镜头。默认不传尾帧，让模型按描述完成动作；需要控制结束状态时，点「添加尾帧」，选定的尾帧图片才会作为 `last_frame` 发送。新视频不读取前一个镜头的图片或视频，排序变化不会改变首尾帧来源。

尾帧设置支持填写描述生成 1–4 张候选、上传图片、从已有候选中选择和放大查看。生成尾帧时，图片接口收到角色与场景参考图，以及最后附加的当前首帧；提示词指明首帧的参考编号，并描述结束状态。首尾候选共用同一镜头的图片集合，新图不自动替换选择；移除尾帧不删除图片。

[buildVideoPrompt](../lib/video.ts) 在单首帧模式要求从起始状态连续完成动作；只有选定尾帧时，才添加到达指定结束姿势和构图的约束。不要为了衔接而让每段视频都先停住再起步；不同机位或叙事重点的镜头可以正常切换。

AI 拆镜优先保留同场景、同机位下的完整动作，镜头数量仅作参考。在地点、时间、景别、机位或叙事目的变化处切镜；视频目标 2–30 秒，长段在自然节点拆分。每镜头描述包含起始画面、动作过程、结束状态和运镜，静图接口只绘制起始画面。当前每镜头一位说话人的限制仍保留。

| Wan 提示词要素 | 项目数据 |
| --- | --- |
| 画风与整体情绪 | `project.style` |
| 起点画面 | 当前镜头 `selectedCandidateId` 选中的候选图，传为 `first_frame` |
| 终点画面 | 可选的 `selectedEndCandidateId` 候选图；选中时才传 `last_frame` |
| 动作和运镜 | `shot.description`；若故事板新增动作字段，优先使用专门的动作字段 |
| 对白与说话方式 | `shot.dialogue`、说话角色名称及 `shot.voiceInstruction` |
| 开口前停顿 | `shot.audioLeadIn`，在时间线上描述先静默再开口 |
| 画幅和时长 | `project.aspectRatio`、`shot.duration`；Wan 请求时长为 2–30 秒整数 |
| 画面文字约束 | 始终要求模型不生成画内字幕；预览字幕由播放器按镜头设置叠加 |

每个镜头可保留多个候选视频，并在「成片视频」下拉框或候选卡片中选定一个。成片预览以选定视频为准，输入变化仍保留并播放当前选择，同时提示更新；旧候选没有原对白快照，与当前设定不同的视频暂不叠加字幕，避免新对白与原视频声音不一致。新视频生成完成不会替换已有视频选择。选择自动保存到作品，视频生成期间仍可切换已有候选。

新视频生成期间，当前描述和首尾选图锁定，其他镜头仍可编辑并行生成；镜头顺序不参与新视频来源判定。任务保存独立来源标记、输入指纹和原始请求时长，重新打开作品后查询结果仍采用原始记录。换图或修改生成设定提示更新，旧候选保留。

历史视频继续按其实际输入判断：单首帧视频沿用原判定；链式视频仍比较原前驱和两张图，运行中的链式任务继续锁定原前驱。新增尾帧会提示旧视频需要更新，重新生成才使用独立首尾帧。已有作品不会自动重拆镜头或重生成素材。

`first_frame` + `last_frame` 是独立的素材模式，请勿同时附加参考角色图片或参考音频；如果确实需要多张角色参考或音频参考，应改用 `reference_image` / `reference_audio` 组合模式。项目未自动裁切两张图，制作时应自行选择画幅和构图相容的图片。
